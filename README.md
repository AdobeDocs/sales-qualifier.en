# Contribute to the documentation

We welcome contributions from community members and Adobe employees.

## Adobe open source code of conduct

This project follows the [Adobe Open Source Code of Conduct](code-of-conduct.md) or
the [.NET Foundation Code of Conduct](https://dotnetfoundation.org/code-of-conduct).
For more information, see [Contributing](contributing.md).

## How to contribute to Adobe content

If you are not an Adobe employee, you can submit a community contribution. The documentation team reviews contributions in the public repository and synchronizes approved changes with Adobe's internal systems.

If you are an Adobe employee, contribute directly to the private [Adobe GitHub repository](https://git.corp.adobe.com/AdobeDocs/). For details, see the Adobe Experience League authoring guide for Adobe employees.

## External contributors

### Minor changes

If you are contributing a minor update:

1. Go to the topic that you want to edit.
1. In the **Was this content helpful?** banner at the bottom of the page, select **Detailed feedback options**.
1. Select **Suggest an edit** and submit a pull request (PR) with your changes.

   See the [Adobe Docs contributor guide](https://experienceleague.adobe.com/en/docs/contributor/contributor-guide/introduction) for more information.

Minor corrections or clarifications you submit for documentation and code examples in this repo are covered by the Adobe terms of use.

### Major changes and new topics

To create a topic or propose a major change, submit an issue from the **Issues** tab in the appropriate Git repository. A documentation team member works with you to agree on a plan and publish the revision.

>[!NOTE]
>
>If you submit significant documentation or code changes, the pull request prompts you to complete an online contributor license agreement (CLA). Complete the CLA before the documentation team reviews your pull request.

### Tools

Use the GitHub interface for basic edits. For major contributions, fork the repository.

See the [Adobe Docs contributor guide](https://experienceleague.adobe.com/en/docs/contributor/contributor-guide/introduction) for details.

## Internal contributors

If you are an Adobe technical writer, program manager, or product developer who authors technical articles, use the [private repository](https://git.corp.adobe.com/AdobeDocs).

## Format your topic

Articles in this repository use GitHub Flavored Markdown. For help, see:

* [Markdown basics](https://help.github.com/articles/getting-started-with-writing-and-formatting-on-github/)
* [Printable Markdown cheat sheet](https://guides.github.com/pdfs/markdown-cheatsheet-online.pdf)

## Labels

The public repository automatically assigns labels to pull requests:

* **Change sent to author**: The author was notified of the pending pull request.
* **ready-to-merge**: The pull request is ready for review.
